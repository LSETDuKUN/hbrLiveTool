# 攻击前效果与天赋审查

## 已验证的数据

本地 CN `BIYamawakiSkill55`（超级大爆炸）为 0 SP、10 Hit；附带 Self Funnel part，power=3、value=0.25，明确在 Before 时机施加，Count 1，Default 限制。自动试算加入 3×25% 连击，并纳入有效连击的同类筛选和概率分布权重。效果已有同源实际状态时不再重复加入。After、带未解析条件、成长可变量的连击不提前猜测。

`Passive.ConsumeSpAttackUp01`（丰后）与 `Passive.ConsumeSpAttackUp03`（山胁）资料均为：

- OnPlayerTurnStart；全体友方中使用非普通攻击且 ConsumeSp()<=8 的对象获得 100% 普通加攻。
- 包含恰好 8 SP，并非严格小于 8。
- 当前资料 exitCond=PlayerTurnEnd、exitVal=[1,0]，并非永久效果。用户描述为次数 Buff，本实现保留资料中的持续类型；两者都参与有限期普通加攻的两层/单独发动覆盖，不将 +200% 当作不可覆盖的被动增幅。
- 不根据风格或突破等级猜测拥有：只对当前队伍 runtime passiveSkillList 中实际存在的标签预计算。本次新采样确认两名角色均加载对应天赋，usedCount=0、limitCount=0。
- 目前仅对确认的 0 SP 技能，或调用方明确提供实际消耗的情况应用这两个已核对规则。其他消耗不凭基础 SP 推断实际 SP，避免减耗、变动消耗等误判。尚未发现可直接读取的通用“条件成立”布尔结果，没有调用游戏逻辑方法。
- 已物化的同源实际 Buff 按实例数抵扣预测项，避免 +100% 被计算两遍；强单独发动加攻可以覆盖这两项。

资料子集：`tests/fixtures/low_sp_passives.json`。读到的天赋在不同风格的突破阶数不一定相同，因此不固定写死“突破三已解锁”。

## 审查范围与边界

战斗采样读取每名角色已加载的天赋/被动清单、运行时名称、描述、条件、使用次数及次数上限，匹配本地 part 的施加对象、效果、数值与目标条件。技能选项同时保留基础 Sp 字段，不冒充实际消费。

“天赋与被动审查”页可查看全队数据，包括实际加载的 `Passive.SupportSkill_*` 共鸣来源。此次采样读到了 31A/31B/31D 共鸣标签与运行时描述，但这些标签未匹配本地效果表，明确标记待核对，不自动补全或假定满级。

条件分为“已支持低 SP 条件”“条件待核对”“效果/时机待核对”。已施加 Buff 继续读取真实状态；未经验证的 SP、DP、前排、概率、时序条件仅展示原文，不执行条件字符串、不预加效果。当前状态中已有的鬼神等专用逻辑仍保留，审查页并不代表所有天赋已实现自动预测。

UI 改用挂件已有 RoundedCard / RoundedButton，调亮紫色背景并为乘区使用不同色调。保留滚动表单、概率曲线与原始参数页。

回归覆盖：超级大爆炸 13 段（10 主 Hit +3 追加）、两名已拥有天赋合计 200%、单独发动覆盖、普通加攻只取两层、实际状态出现后去重、8/9 SP 边界、未解锁不猜测、条件/时机变化后不预加、未知共鸣保留、圆角组件与审查页存在。
