# HBR Live · 星屑战斗手帐

面向《Heaven Burns Red / 炽焰天穹》国服 PC 端的 **Windows 战斗记录助手**：只读游戏内存，实时展示敌方 DP/HP、角色技能与命中伤害，并提供可离线查询的星屑资料室。

本项目已从旧 OCR 工具拆分，独立运行，不需要截图识别，也不依赖旧项目目录。

- 当前仓库：[LSETDuKUN/hbrLiveTool](https://github.com/LSETDuKUN/hbrLiveTool)，主分支 `main`。
- 旧项目：[LSETDuKUN/hbrTool](https://github.com/LSETDuKUN/hbrTool)，保留 OCR 与早期实验历史。

## 当前进度（2026-10-10）

已具备可使用的战斗采集与资料查询流程；用户已反馈核心数值准确，多目标更新可用。目前仍是依赖游戏版本的工具，并非覆盖所有技能和战斗机制的通用解析器。

| 功能 | 当前情况 |
| --- | --- |
| 自动定位战斗 | 进入指令选择画面后连接；只读访问，首次扫描通常需要几十秒 |
| 敌方 DP/HP | 每个敌人独立卡片，直接读取当前值；破盾、回升和下一条 DP 恢复随实值更新 |
| 多目标 | 同时显示多个敌人，编号按首次出现顺序固定；离场保留最后读数并标注；同一战斗对象内出现的新敌人追加显示 |
| 行动与伤害 | 记录角色、技能、命中目标、逐目标合计、本体与连击珠命中、暴击标记；同一行动后续命中更新原记录 |
| 无伤害技能 | 根据观测到的执行条目记录“谁用了什么、作用于谁”；暂不解释增益、减益等特殊效果，覆盖范围仍需更多实战验证 |
| 资料室 | 角色、风格头像、技能卡片、敌人资料、结构化数值与只读 SQL；逐 Hit 信息以数据源是否提供为准 |
| 本地记录 | 自动保存会话 JSONL，可导出本场摘要；暂停/继续沿用本场数据 |
| 界面 | 圆角面板、宽版/紧凑模式、置顶、透明度、可拖动缩放；诊断日志与资料室独立窗口 |

验证基础：31 项自动化测试通过，包含既有破盾/过量伤害录制数据回放、事件去重、友方效果不计伤害、多目标状态与界面测试。自动测试不代表所有游戏机制均已验证。

## 快速开始

需要 Windows、Python 3.12（含 Tk）及国服 PC 游戏。当前适配依据是 **国服 6.5.10** 的运行时布局；游戏更新后可能需要重新适配。

```powershell
git clone git@github.com:LSETDuKUN/hbrLiveTool.git
cd hbrLiveTool
python -m pip install -r requirements.txt
```

1. 双击 **启动HBR Live.bat**，接受管理员权限提示。
2. 进入战斗并停在指令选择画面，点击 **连接战斗**。
3. 等待“内存已连接 · 可以行动”后攻击。
4. 每场新战斗重新连接；连接失败会保留上一场结果，成功后开始新的统计。

启动器优先使用本机 `F:\python\pythonw.exe`，不存在时查找 PATH 中的 `pythonw.exe`。也可在具有相应读取权限的终端运行：

```powershell
python -B -m hbr_live_app
```

全新克隆不含资料缓存：打开 **星屑资料室**，先点击 **同步网站资料**，再按需 **同步头像**。已有缓存时可离线查询。缺少资料时战斗采集仍可使用，但部分名称可能显示内部标识。

## 如何读面板

- **敌方卡片**：每个敌人独立显示名称、DP／HP 和行动预告。点击名称在中文、已匹配的国际服名与内部名称间切换；底部“名称与行动规则”可查看完整名称和 DP／HP 阶段规则。名称以实际敌方资料 ID 和关卡标签匹配，不把同类 Boss 的其他版本混用。
- **掉血残影**：DP／HP 实值和主条即时更新；0.7 秒内累计减少至少本场观测参考值的 12% 时，粉色残影停留约 0.35 秒，再于 0.7 秒内追上。小额伤害直接更新；回血、参考值变化、暂停和离场会清理残影，不影响记录与合计。
- **技能效果预告**：预告技能下方小字展示 Hit 数、单体／全体、减益／控制等资料效果；资料 power 区间明确标注为“资料威力（非实伤）”，不当作实际承伤估算。多动效果按技能编号对应，卡片自动增高。
- **技能效果**：敌方详情列出资料中已有的目标、伤害类型、蓄力／增益／回复等效果及命中次数；没有文本说明的威力值以原始参数展示，不视作实际伤害。未命名且可确认的普通攻击使用“单体攻击／全体攻击”，原始标签保留在详情。
- **预告显示时机**：角色行动期间保留预告，盾层或条件变化时重新计算；敌方执行期间保留本组行动，整组结束后再显示下一组。排队时提前推进的规则游标不会直接跳到下一组。
- **规则预告与分支**：滚轮中间框突出下一次行动，上方显示刚观测到的技能，下方最多列两步后续推演；读到进度变化后自动滚动过渡。同轮多动标成 `1 技能甲 · 2 技能乙`，随机候选分色展示条件权重占比；未知条件不计算百分比，展开可查看条件及不成立时的后续候选。支持敌人数、观测技能次数、蓄力状态／阶段、DP/HP 比例、破坏率、Turn 的基本比较与逻辑组合。条件不满足时按规则顺序寻找候选，跳过语义仍需实测；不宣称后续一定发生。只在分支唯一且条件可判断时继续推演，假设敌人数和阶段不变，不自动假定全局 Turn 加一。
- **机制边界**：普通击破后使用 HP 阶段规则和实际进度；无盾敌人及没有破盾行动表的敌人保留主行动表。多层盾按实际层索引匹配运行时行动表，阿蒙已验证第一次破盾切到 DP2；倒地时展示恢复后候选，不闪烁。技能次数来自本次观测，仅从首回合、敌方尚未行动时连续采集才允许未见技能按零次推演；中途连接、暂停或采样间隔超过 0.6 秒后保留未知。未支持的特殊状态、仅一次规则是否触发、未匹配的多段血条、覆盖规则和循环重置不冒充已确认。权重占比是候选集合内的资料权重，不是经过实测验证的概率。
- **行动轴显示与保存**：默认收起，后台照常记录；勾选“显示行动轴”可嵌入主界面。战斗自然结束后询问是否保存，支持 PNG 图片（长轴分页）和 HTML 表格（可展开完整记录），也可随时手动保存。开发阶段选择不保存只跳过导出，`sessions` 诊断样本暂时保留。
- **行动表格**：一次指令行动占一行，第一列为 `Turn 1 / Bonus 1 / Extra`（无 OD 或追加时省略对应部分），后面三列按游戏画面从左到右展示前排角色与技能（内部站位顺序为 2、1、3）。单人追加在对应位置展示，其余两格为 `/`；三人追加则三格都有内容。同一角色多次发动会保留全部技能，实际行动先后顺序可在详情查看。`/` 表示尚未观测到该位置的行动，采集途中会随技能发动更新。
- **头像与定向友方技能**：默认使用本地数据库按风格 label 精确匹配的头像，点击头像或“切换头像 / 角色风格”按钮可切换为文字。缺图回退角色／风格名，不联网下载。记录到唯一非自身友方目标时，在技能旁展示目标头像／文字；群体和未知目标不猜作单体。新日志保留实际目标风格，旧记录缺少该信息时不反推。导出随当前头像／文字模式，PNG 保留头像与目标，HTML 内嵌头像可离线打开。头像、技能和目标在同一水平中线上整组居中。
- **折叠详情**：伤害、作用目标、逐 Hit 默认收起；选择表格行后点“展开本行详情”，或双击该行打开详情窗口。宽版加宽以展示三列，紧凑模式仍保留所有列，可横向滚动。每批行动重新采集前排站位并保存；位置缺失的事件留在详情标注，不按观测顺序补位。角色／风格用小字淡色，技能用大字加粗暖色，回合标签保留颜色并以斜杠分隔在同一行显示，表格内容居中。
- **行动风格**：从行动角色当前卡牌读取风格标识，以本地国服资料匹配名称，表格展示“角色 / 风格”及技能。长名称省略，展开可看完整名称与原始标识；资料未收录时显示标识，不从技能反推风格。部分资料名称为英文，旧记录没有风格字段时保持原有显示。
- **指令行动分界**：每次沿当前战斗状态机读取实际节点，手动“指令选择”和“自动”准备阶段均能建立新批次；观察到已执行角色事件后才显示表格行。中途连接／暂停漏掉的行动不补算。OD 内追加同时保留 Bonus 与 Extra 标签。分组不可读时继续记录角色行动，并标记回合未识别。
- **记录格式**：新会话及导出摘要使用 schema 2；角色事件含 `command`（Turn、Bonus、追加标记、批次等）、`actor_id` 和 `actor_position`。原有伤害、目标、命中字段保留；JSONL 的 `turn_context` 同时保存状态诊断信息。普通、连续追加、一级后置 OD、OD 内追加和自动流程已有录制回放覆盖；前置和多级 OD 待更多实测。
- **敌方状态**：宽版可同时查看三个敌人；空间不足或紧凑模式时滚动查看。列表里的“敌1”等编号与命中明细对应，不承诺对应游戏画面的左右顺序。
- **量表**：右侧是当前 DP/HP，左侧标注最近一次采样变化；比例参考连接以来观测到的最大值。中途连接时不冒充初始满值，也不补算此前伤害。
- **指令伤害**：主卡显示 `TurnMaxDamage`（本场单次指令累计伤害的最高值），副卡显示 `TurnDamage`（当前指令累计伤害）。包括该指令的追击与连击珠；命中更新原事件，不重复累加。新指令首次观测到行动时从零计起，短暂显示“已有值 + 新增值”后收敛为合计。尚未确认指令的伤害暂按独立事件保留，确认归属后合并。本场总伤害仍保留在摘要和导出中。
- **追击与小按钮**：`Passive.Pursuit_` 追击在表格中简化为前一行动旁的“追”，明细与伤害保留。特殊指令对象的小按钮事件单列，不占用普通指令，伤害先计入待执行指令，再与随后普通行动合并，纳入 TurnDamage 和 TurnMaxDamage。鬼神化等强化启动、局内风格／形态切换直接读取角色状态变化，单列一次；连接时已有状态不冒充新发动。Saki 已用实录验证，其他角色仍需继续积累样本。
- **显示伤害**：保留游戏行动中的显示伤害，包括过量部分。**显示伤害不等于 DP/HP 实际减少量**，资源值不会靠减去该合计推算。
- **行动明细**：选择记录可看逐目标伤害和逐 Hit 数据；双击在独立窗口展开。无对敌伤害时显示“已发动”或“未见伤害”，不将友方效果数值当成伤害。
- **暂停**：用于思考。暂停时不要行动；期间执行且消失的行动无法保证补回。

## 文件与迁移

```text
hbr_live_app/   采集、事件归并、状态模型与战斗面板
hbr_data/       资料同步、SQLite 查询、头像与技能详情
tests/        回归测试与精简录制样本
data/quest/   本地资料与头像缓存（不上传 Git）
sessions/     战斗会话记录（不上传 Git）
 settings.json 窗口设置（不上传 Git）
```

**整个项目文件夹可以移动或改名。** 路径按项目自身位置解析，不依赖原来的父目录。

- 同一电脑迁移：退出挂件后移动整个文件夹，保留隐藏的 **`.git`**，远程仓库绑定、分支与提交记录会一并保留。
- 同时保留 `data`、`sessions`、`settings.json`，即可带走离线资料、对局记录和布局设置。
- 换电脑：仍需安装 Python 和依赖；这些运行环境不打包在项目里。
- Git 克隆或 GitHub ZIP 不含本地缓存/记录；ZIP 也不含 `.git`，不自带远程绑定。

停止或关闭窗口时，会等待读取线程退出并关闭记录文件。菜单可打开记录文件夹、导出摘要和查看诊断。

## 已知边界与后续方向

- 仅使用 Windows 查询/读取接口，不注入、不修改游戏内存或文件；权限不足或布局不兼容会报错。
- 读取多个残留战斗对象时不猜选；若无法连接，可重新进入战斗或重启游戏。
- DP 回升不等于破盾计数；阿蒙按运行时盾层索引记录锁盾，其他未确认机制不猜测。
- 极短的行动若在两次采样之间出现并消失，仍可能漏记；无伤害技能、召唤/增援和特殊战斗需要继续积累样本。
- 当前支持记录和导出，尚未提供完整历史对局回放界面；特殊效果语义分析留待后续。
- 资料室基于 hbr.quest 的公开数据与本地快照；不同地区版本、缺失字段、逐 Hit 缺项不能自行补成确定值。

## 开发入口

```powershell
python -B -m unittest discover -s tests
```

采集流程：`runtime`（只读系统接口）→ `source`（自动定位与采样）→ `events`（按行动归并已执行命中）→ `model`（独立资源状态与总伤害）→ `app` / `enemy_cards`（面板）。

`hbr_data` 提供资料同步、结构化查询及详情展示。行动记录保留目标与命中明细，资源状态独立保存，为后续分析留出接口。

### 全 SP 技能

- `AttackBySp` 按来源的效果封顶 SP（如三枪狂袭 30 SP）缩放最小、最大威力，再计算等级、差值、宝珠和超差。封顶限制效果，不代表实际消耗也封顶。
- 自动填充默认使用当前 SP；预计剩余及预计消耗字段仅供核对，避免采用缓存。可手动输入行动前预计消耗；SP 缺失或为零时不生成该技能的基础伤害。
- 破坏倍率默认保留来源数值；确认为随 SP 线性增长的技能可单独勾选缩放。疾如风的充能分支按充能状态选取，未知状态不猜测分支。
- 本轮实时 SP 采样被进程访问权限阻止；读取字段已用保存的内存样本验证，实时预选变化仍待验证。

### 跨盾浮动概率

- 每 Hit 独立 U(0.9,1.1)。第 k 段破盾概率为 P(前 k 段 DP 伤害 ≥ 盾量) − P(前 k−1 段 ≥ 盾量)。正伤害保证只存在一个首次破盾段。
- 固定破盾段后，DP 有效伤害恒为盾量，溢出丢弃；破盾段结算后增加破坏率，后续 HP 段使用相应破坏率及独立浮动。对各分支数值卷积再混合，无需假设总伤害为正态或均匀分布。
- 连击增量、上限截断、DP/HP 特攻及当前池差异均沿用逐段模型。伤害轴表示实际扣除的 DP+HP；最后一段破盾或 HP 耗尽可能产生点质量，金色竖线单独标注其概率，不并入连续密度。
- 输出均值、中央 90% 区间、破盾段概率和模型内击杀概率；均值按各分支自身区间积分，不受绘图网格宽度影响。分布采用有限网格数值积分，极小尾部概率存在精度限制，不是精确有理数答案。
- 假设固定增益、无伤害衰减；支持普通单层盾及下述阿蒙锁盾，不处理行动中新生状态、其他多层盾或随机暴击。原来的逐段明细仍为无浮动基准，不冒充随机期望。

### 自动承伤池与结果呈现

自动填充后默认选择“自动跨 DP/HP”，根据每段命中前剩余盾量判断承伤池；HP/DP 特攻分别保留，HP 段使用 HP 特攻以及池相关增益差异，手动改动仍保留。逐段参数缺失时明确提示补充，不退回起始池计算整招。单池选项保留用于人工核对；阿蒙锁盾以外的多层盾暂不自动跨池。

乘区试算首页顶部显示平均伤害、中央 90% 浮动区间和概率图。完整乘区明细、模型说明、Hit 权重、破盾分支及击杀概率默认折叠；单独的概率页已合并进主页。跨池平均值仍表示有效 DP+HP 扣除量。

### 阿蒙锁盾

- 沿用游戏实际 `dpIndexInternal` 记录当前盾层，以本地敌人 bars 数据提供总层数和下一层容量，不通过 DP 回升次数猜测盾数。盾状态随快照进入 sessions 记录。
- 阿蒙规则按用户确认：一个真实 Turn 最多破一层，破后可削下一层但保留 1 DP；追加回合、指令切换及 OD bonus 不重置。最后一层未锁时可正常破盾进入 HP；其余层仍按 DP 特攻计算。
- 独立记录每个敌人的 Turn 与层索引变化。中途接入已破盾状态、超过 0.6 秒的采样间隔、无法归属的换层保持本 Turn 记录未知；下一次连续观测到真实 Turn 切换后才重新确认。未知时阻止自动跨层计算。
- 概率分布按首次破盾段混合：下一层继续使用 DP 伤害，锁定上限为下一层 DP−1；不会对尚有锁盾的敌人报告 HP 伤害或击杀概率。达到锁盾上限的概率作为点质量展示。
- 锁盾规则仅用于阿蒙标识族，未泛化给所有多层盾敌人。当前层与 Turn 已有样本和回归覆盖；下一层容量来自本地资料，实际新版本仍需游戏内复核。
